# Codex Session Organizer

<p align="center">
  <img src="./assets/readme/hero.svg" width="100%" alt="Codex Session Organizer：新会话命名并归入自选分区；每轮评估，长期目标实质变化时更新右侧目标。下方条目为机制示意，不是真实截图。">

给 **macOS Codex 桌面端**用的轻量插件。首次完成实质任务时，把新会话命名为「主题对象｜持续目标」，归入你选择的侧栏分区；后续每轮评估主线：普通追问沿用标题，长期目标实质变化时只更新右侧目标；分区保持不变。也可选择开启**旧 Codex 会话续聊整理**：只接管你再次发送消息的会话，不扫描或批量改历史。

**macOS 桌面端** · **Python 3.9+** · **MIT 开源** · **本地状态，无额外 API Key**

[安装](#安装) · [工作原理](#工作原理) · [使用指南](docs/usage.md) · [v0.3.0-rc.1 下载](https://github.com/Stanley-baby/codex-session-organizer/releases/tag/v0.3.0-rc.1)

| --- | --- | --- |
| 排查插件 → 修复 → 测试 | 会话插件｜稳定命名与分类 | 开发工具 |

上图和表格均为虚构示例。分区名称与归属描述由你决定；标题目标不超过 24 个字符。

## 安装

需要支持插件 Hooks 和原生侧栏管理工具的 **macOS Codex 桌面端**，以及可运行的 `codex` 命令和 Python 3.9+。

### 1. 安装插件

```sh
codex plugin marketplace add Stanley-baby/codex-session-organizer --ref v0.3.0-rc.1
codex plugin add codex-session-organizer@codex-session-organizer
```

通过 GitHub marketplace 分发，固定到 `v0.3.0-rc.1` 以便复现；不是官方公共插件目录的已审核上架项目。已有旧版安装请先看[更新步骤](docs/usage.md#更新)。

### 2. 设置分区，审核 Hooks

在 Codex 插件设置中运行 **Setup**，或在会话中选择本插件的 `session-organizer-setup` 技能，发送：

```text
请使用 Codex Session Organizer 的设置技能初始化。
先读取我的侧栏，与我确认分区名称和归属描述，再复用或创建分区。
只整理初始化之后的新会话，保留历史会话、项目和置顶状态。
设置完成后告诉我如何审核两个 Hook，并验收普通追问保持、长期目标变化时更新。
```

设置技能会检查环境、确认分类、读取真实分区 ID，并保存本机配置。缺少分区时，经你同意后创建。

随后在 Codex 的 **`/hooks`** 中审核并信任本插件的 `UserPromptSubmit` 和 `PostToolUse` 两个 Hook。安装和启用不会自动完成信任；必要时保存工作后重开桌面应用。

### 3. 新开会话，试三轮

初始化会话不在接管范围，请另开一个新会话，**直接在输入框发送**：

1. 「给我三条 Codex 多会话管理建议，每条不超过 20 字。」不额外要求改名；任务完成后，确认首次标题符合“主题对象｜持续目标”，并查看分区。首次命名无需先发生目标变化。
2. 在同一会话追问：「把第一条改得更口语化，其他保持不变。」确认标题与分区保持不变。

3. 明确补充：「目标改为给团队交付一份可长期维护的会话管理规范，不再只是个人建议；请给出规范初稿。」完成后核对左侧主题对象不变、右侧目标反映新主线，分区不变。

语义判断由模型完成；检查更新是否合理，不要求逐字匹配某个示例标题。工具转发消息不替代真实输入验收。

## 工作原理

<p align="center">
  <img src="./assets/readme/workflow.svg" width="100%" alt="每轮读取当前状态 → 完成用户任务 → 首次命名或后续目标校准 → 侧栏回读确认。">
</p>

**每轮评估 → 完成用户任务 → 首次命名 / 后续校准 → 回读记账。** Hook 提供规则，模型判断语义，原生工具执行；侧栏回读吻合后才记录成功。

- **首次命名**：首次自动标题尚未确认时，按会话结果命名；不会因目标未变化或默认标题与空记录不同而跳过。用户明确指定及已观察到手动修改的标题仍受保护。
- **稳定校准**：结合会话主线与用户已明确或认可的目标；只要仍在服务原目标，就保持标题。新主线有明确依据、旧标题已明显失真才更新右侧，不要求固定口令。修复、测试可以是核心目标，也可以是推进步骤，不按动词机械判断；左侧主题对象保持不变。
- **分区独立**：分区仍为一次确认，不随每轮目标变化来回移动。标题更新先读取当前侧栏，同轮回读吻合才确认；每轮最多确认一次，失败不循环重试。
- **保留人为选择**：已观察到的手动改名和用户明确指定的标题受保护；只有用户明确要求才恢复自动校准。保留自定义分区、项目分区与置顶。
- **新会话默认，旧会话可选**：默认按首次初始化时间过滤 UUIDv7；开启旧会话整理后，只有再次发送消息的旧 Codex 会话才接入。仅打开、读取侧栏或后台工具事件不触发首次接管，不批量处理历史。
- **状态留在本机**：Python 标准库、文件锁和原子写入；脚本不调用第三方接口，不直接写聊天数据库。

## 日常使用

直接告诉设置技能：「检查插件」「调整分类」「暂停自动整理」或「恢复自动整理」。调整分类保留首次接管时间和已有完成状态。也可以明确说「保护当前标题」或「恢复自动目标校准」。

### 旧会话续聊整理（可选）

新安装和升级默认保留原接管范围。需要整理旧 Codex 会话时，向设置技能发送：

```text
请开启旧 Codex 会话续聊整理，保留原分区映射、初始化时间和已有状态。
只接管我再次发送消息的旧会话；完成实质任务后整理，不批量改历史。
保留已保护或明确指定的标题、自定义分区、项目归属和置顶。
```

开启后，首次续聊仍需完成实质任务才执行整理，随后沿用相同的目标校准和原生回读规则。关闭此选项会停止旧会话整理，不撤销已确认的侧栏修改。首次观察前的手动标题可能没有机器标记；重要名称请明确告知保留。

### ChatGPT 会话

**本版不提供 ChatGPT 逐轮自动整理。** 2026-10-16 的真实 ChatGPT 续聊已完成，但没有触发本地命令 Hook；Codex 同期对照输入正常触发。能读取、改名或移动 ChatGPT 会话，不等于能在每轮聊天时自动执行。本项目没有用定时轮询或手动整理冒充同等支持。[验证说明](docs/verification.md#chatgpt-真实触发验证)

高级配置、管理命令及状态目录说明见[使用指南](docs/usage.md#配置诊断与暂停)。模型执行与数据处理仍遵循你的 Codex 产品及账号设置，详见[数据说明](PRIVACY.md)。

### 更新

当前 CLI 切换固定版本时需先移除同名安装源再重新添加；按[更新步骤](docs/usage.md#更新)操作，保留状态目录，在 `/hooks` 检查更新后的定义是否需要重新审核。

### 卸载与回退

先让设置技能暂停插件，再执行：

```sh
codex plugin remove codex-session-organizer@codex-session-organizer
```

卸载保留本地状态和已整理的侧栏。移除安装源、还原标题与分区的步骤见[卸载与回退](docs/usage.md#卸载与回退)。

### 从个人内联 Hook 版本迁移

先保留旧版备份，按旧版说明仅移除它自己的两条 Hook，再初始化新版并验收。两套整理器不要同时启用；检测到旧版注册时，新版会停止初始化。[查看迁移与恢复步骤](docs/usage.md#从个人内联-hook-版本迁移)。

## 支持范围

`v0.3.0-rc.1` 为公开测试版，面向 **macOS Codex 桌面端**。受测客户端为 codex-cli `0.162.0-alpha.17.2`；Windows、Linux、远程主机及 CLI 内的侧栏整理尚未验收。

侧栏临时 ID 仅在本机存在明确绑定时解析；绑定缺失、工具失败或回读不匹配时不记为完成。目标变化的语义判断、命名与分类由模型完成，不是确定性强制规则；24 字是提示目标。每轮会增加管理上下文与必要的侧栏读取，不另接模型服务。第一次侧栏观察前的手动改名可能没有机器标记；缺少原生工具时跳过整理，正常用户任务继续。[完整兼容性说明](docs/usage.md#支持范围) · [故障排查与已知边界](docs/usage.md#故障排查)。

**验证记录**：本版 70 项隔离自动测试通过；旧会话的选择性接管、状态续用、手动保护和回读逻辑已覆盖，真实旧会话续聊验收仍待完成。v0.2.2 曾完成全新会话的真实首次命名与分区验收，该结果不替代本版旧会话验收。[验证说明](docs/verification.md) · [自动测试](https://github.com/Stanley-baby/codex-session-organizer/actions)。
