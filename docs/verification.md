### 2026-10-17：目标转向、自动分区与手动保护专项验收

专项验收已通过。使用已有临时 Codex 会话，其原自动标题为“Codex 会话｜制定整理建议”。准备时通过原生工具将该测试会话移回普通列表，仅重置分区完成标记，保留已管理标题和目标校准状态；未修改插件源码或全局设置，未手工写入验收成功状态。

用户直接输入将个人整理建议转为全团队长期协作规范的请求，未要求改名或搬动。首次执行依次查看侧栏、改名一次、移动分区一次、回读确认；之后用户再次输入同一请求，只读取侧栏，没有重复改名或移动。

## ChatGPT 真实触发验证

2026-10-16 在现有 ChatGPT 会话中，由用户直接输入三条工作日报结构建议的普通文字请求，实际回答已完成。临时本地检测位于 UUID/历史过滤之前，仅记录事件类型、会话/轮次标识和字段名，不记录聊天正文。

检测窗口内没有该 ChatGPT 会话的命令 Hook 事件；同一窗口用户回到 Codex 直接回复时，正常收到 `UserPromptSubmit`，构成正向对照。此前启用与信任检查通过。临时检测已撤下，原脚本恢复，原配置和会话状态未变化；私人 ID、完整状态和日志不进入本仓库。

结论仅针对该真实入口：目前的本地命令 Hook 方案未提供 ChatGPT 逐轮自动触发，不能因原生工具支持 ChatGPT 改名/移动就宣称同等自动整理。未使用定时轮询或手动流程冒充完整功能。

[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)说明：云端编排不支持本地配置/插件命令 Hook，即使工具在本机执行；本地编排的 Work / Codex 与企业管理员远程 MCP Hook 是不同路径。此次结果不推广为所有 ChatGPT 或 Work 入口永远不支持。

## 复现

```sh
python3 -m unittest discover -s tests -v
sh -n hooks/run.sh scripts/python.sh
```

隔离安装示例（在仓库根目录执行）：

```sh
TEST_HOME=$(mktemp -d)
CODEX_HOME="$TEST_HOME" codex plugin marketplace add "$PWD"
CODEX_HOME="$TEST_HOME" codex plugin add codex-session-organizer@codex-session-organizer
CODEX_HOME="$TEST_HOME" codex plugin list --json
CODEX_HOME="$TEST_HOME" codex plugin remove codex-session-organizer@codex-session-organizer
```

此测试只检查打包/安装，不启动带真实账号的会话。临时目录请在检查完后自行清理。仓库不包含原用户的安装备份、状态或验收快照。
