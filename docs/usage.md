# 使用指南

[返回项目首页](../README.md) · [验证说明](verification.md) · [数据说明](../PRIVACY.md)

初次使用请先按首页完成安装、初始化与三轮验收。本页保留高级配置、版本维护、旧版迁移和排错细节。

## 配置、诊断与暂停

日常直接告诉设置技能「检查插件」「暂停自动整理」「恢复自动整理」「调整分类」即可。调整分类不会重置首次接管时间，也不会重新整理已完成的会话。

高级用户可在插件根目录调用管理脚本。以下命令的当前目录应是插件根目录：

```sh
sh scripts/python.sh scripts/manage.py doctor
sh scripts/python.sh scripts/manage.py pause
sh scripts/python.sh scripts/manage.py resume
```

`doctor` 检查本地前提；它不会把未检查的 Hook 信任或原生工具可用性报告为通过。

手动初始化可运行 `sh scripts/python.sh scripts/manage.py init mapping.json`；`mapping.json` 内容如下。**请先用原生侧栏回读，将示例 ID 替换为自己机器上的真实 ID**：

```json
{
  "auto_create_sections": false,
  "sections": [
    {"name": "开发工具", "id": "YOUR_REAL_SECTION_ID", "description": "软件、插件、脚本和开发环境"},
    {"name": "学习研究", "id": "YOUR_OTHER_SECTION_ID", "description": "独立调研、知识学习和阅读笔记"}
  ]
}
```

配置保存在 `${CODEX_HOME:-$HOME/.codex}/state/codex-session-organizer/settings.json`，同目录每个已接管会话一个状态文件。首次写入目录权限 700、文件权限 600。不要把整个状态目录提交到仓库。

为跨版本保留“已整理”状态，数据使用上述固定目录，而不是版本化的插件缓存。卸载/重装和升级时保留此目录；删除它再初始化会重设接管边界。脚本尊重 `CODEX_HOME`，便于隔离测试。

## 旧 Codex 会话续聊整理

`manage_existing` 是可选布尔值，默认关闭；在上面的映射 JSON 顶层加入 `"manage_existing": true`，保留现有 sections 后再次 `init` 即可开启。仅使用真正的 JSON `true` / `false`，不使用字符串。再次初始化省略此字段会保留原选择，设置 `false` 会停止旧会话整理。暂停整个插件仍使用 `pause`。

开启保留原 `installed_at_ms` 和历史排除列表，不遍历或创建历史会话状态。旧会话首次收到有轮次 ID 的 `UserPromptSubmit` 后接入；只打开会话、后台工具或本地控制命令不会首次接管。问候、澄清仍按原规则暂缓，完成实质任务后才命名/分区。接管后只跟踪当前会话和同轮工具回读，不改其他旧会话。

明确指定和已观察到的手动标题、已完成状态、自定义/项目分区与置顶继续保留。首次观察之前的手动标题没有完整标记，重要名称请先明确要求保留。关闭旧会话选项不会撤销侧栏修改或删除状态；重新开启仍复用已有记录。

验收：选择一个初始化之前的 Codex 会话，直接输入实质任务，确认完成后命名与原生回读；再普通追问，确认标题不动；再明确改变主线，确认只更新右侧。检查未续聊的其他历史会话保持不变，置顶/项目归属仍保留。此流程需用户真实输入，合成事件不替代验收。

## 自动新建分组

`auto_create_sections` 为可选布尔值，新安装默认关闭。保留当前完整映射，在初始化 JSON 顶层加入 `"auto_create_sections": true` 后执行 `init`；设为 `false` 关闭，省略则保留原选择。`doctor` 显示当前策略。该功能仅覆盖已接通本地 Hook 的 Codex 会话，不代表 ChatGPT 普通会话已接通。

首个实质任务后，先读取真实侧栏；已有合适分区就复用。仅类别清晰、适合未来同类会话且现有分区都不合适时新建，单次事项和歧义保留普通列表。已有完成状态、明确保留普通列表的决定、项目归属和置顶保持；不扫描全部历史，不随每轮追问搬动。

Hook 提供的准备命令为 `session_organizer.py --prepare-section <当前会话ID> <名称> <归属说明>`，仍通过 `sh scripts/python.sh ...` 启动。必须先在同轮原生回读当前未分组本地会话；准备命令返回 `reuse` 或 `create`，后者才授权调用原生创建工具。准备命令本身不创建分区。返回 reuse 后或创建后再次原生回读，Hook 确认唯一名称与真实 ID 后在配置锁内登记，再确认 settings 中 ID 后移动当前会话并回读。仅工具成功、缺失/错误回读、错误轮次或 ID 不足以完成。

每轮最多准备一次，配置上限 20 个。创建成功但移动失败时保留分区，下一轮复用；新轮次会清除过期准备记录，重新读取侧栏。保存失败不直接移动未登记的分区，下轮通过真实侧栏重新登记；不自动删除或合并。旧名称对应 ID 已删除时不自动重建，手动改名的同 ID 可用准备/回读更新映射并保留归属说明。若多个分区同名，或新名称与其他配置冲突，交用户确认。

创建前重读减少重复，文件锁与原子写入防止并发配置覆盖；原生接口没有原子 get-or-create，跨客户端并发创建仍可能重复。这是已知边界，不以文件锁声称原生工具也绝对去重。

真实验收：用户在未分组临时会话直接输入明确新类别任务，确认新建一次、登记、移动及回读；另一个同类会话确认复用，再追问确认稳定。用原生侧栏和本地状态核对，脚本合成事件、准备消息和人工工具调用单独记录，不替代用户输入验收。关闭或回退代码保留已创建分区和会话；用户另选需要清理的测试分组。

## 更新

先阅读目标版本的 Release Notes。受测 CLI 将不同固定版本标签视为不同安装源，因此切换版本时先移除同名安装源，再重新添加。下面只更换本插件的源，保留固定状态目录；已有安装可执行：

```sh
codex plugin marketplace remove codex-session-organizer
codex plugin marketplace add Stanley-baby/codex-session-organizer --ref v0.3.0-rc.2
codex plugin add codex-session-organizer@codex-session-organizer
```

今后升级时将标签换成实际发布的新版本。保留本地状态目录，在 `/hooks` 检查更新后的定义是否需要重新审核。不要直接改插件缓存内的源码；更新可能覆盖缓存。

## 卸载与回退

先让设置技能暂停本插件，然后：

```sh
codex plugin remove codex-session-organizer@codex-session-organizer
```

如果也要移除安装源，再执行：

```sh
codex plugin marketplace remove codex-session-organizer
```

卸载保留本地状态、会话标题、分区及历史；不会自动把已整理的会话搬回去。若需要还原标题和分区，可发给设置技能：

```text
请读取 Codex Session Organizer 的本地状态，列出它已确认修改的会话、原始标题和原始分区。
先给我预览，由我选择恢复哪些项，再通过原生会话工具逐项恢复并回读。
保留我之后的手动修改；不要直接写聊天数据库，不要移动项目。
```

卸载后技能随插件一起移除；如需侧栏还原，请先预览/还原再卸载，或把上述任务交给仍可使用原生工具的 Codex 会话。

### 从个人内联 Hook 版本迁移

本项目的前身可能在用户配置中直接注册 `session_organizer.py`。为避免两个整理器同时运行，管理脚本检测到旧版注册时拒绝初始化新插件。

1. 保留已工作的旧版及其回退备份。
2. 按旧版自己的卸载/回退说明，仅移除旧版的两条 Hook；保留其他插件、信任设置及历史。
3. 再初始化并信任本插件，验收新建会话。
4. 新版首次接管时间从本次初始化开始，不导入旧版的私人会话记录。

若新版验收失败，暂停/卸载新版，再按旧版说明恢复；不要同时启用两套 Hook。

## 支持范围

| 项目 | v0.3.0-rc.2 |
| --- | --- |
| 平台 | macOS Codex 桌面端 |
| 旧 Codex 会话 | 用户明确开启后，续聊接入；默认不接管 |
| ChatGPT 会话 | 不提供逐轮自动整理，真实续聊未触发本地命令 Hook |
| 前提 | 支持插件 Hooks，并暴露原生会话/侧栏管理工具 |
| 命令行安装工具 | `codex plugin marketplace add`、`codex plugin add` |
| Python | 3.9+；自动从 PATH 和常见 macOS 路径查找 |
| 已验证客户端 | codex-cli `0.162.0-alpha.17.2`；详情见 [验证说明](verification.md) |
| Windows / Linux / CLI 内的侧栏整理 | 尚未验收，不作为本版支持能力 |

官方 Hooks 文档说明，云端编排不支持来自本地配置或插件的命令 Hook，即使工具在本机执行；本地编排的 Codex / Work 路径另行适用。ChatGPT 真实续聊结果及同入口限制见[验证说明](verification.md#chatgpt-真实触发验证)与[官方文档](https://learn.chatgpt.com/docs/hooks)。

这不是独立的聊天列表应用。原生工具缺失时，正常用户任务继续，整理要求被跳过。本项目与 OpenAI 无隶属关系。

打包使用官方仍支持的 `.codex-plugin/plugin.json` 格式。发布前实测发现，当前受测客户端加载根目录 portable manifest 时没有发现 Hook，因此本版不同时放置根目录 `plugin.json`，避免已安装却不执行的情况。

## 故障排查

| 现象 | 检查项 |
| --- | --- |
| 安装后没有动作 | 是否完成初始化；两个 Hook 是否被信任；是否新建于初始化之后或已开启旧会话整理；是否直接输入实质任务 |
| `doctor` 通过但侧栏未变 | 本地检查不覆盖运行时信任/工具；请在桌面新会话检查原生工具并回读 |
| 环境没有 Python | 安装 Python 3.9+，让桌面应用可找到解释器，保存工作后重开应用 |
| 只有命名，未完成分区 | 分区 ID 是否仍有效；已有项目分区/置顶会被保留；歧义时保留普通列表 |
| 暂时未命名 | 问候、澄清、等待材料时暂缓；实质任务后仍未命名，检查是否调用改名工具；v0.2.2 已分开首次命名与后续校准规则 |
| 再次初始化后旧会话没变化 | 默认不接管旧会话；明确开启 manage_existing 后需直接续聊，初始化本身不改历史 |
| ChatGPT 续聊不生效 | 本地命令 Hook 没有该入口的真实触发，不属于本版逐轮自动整理支持范围 |
| 检测到旧版冲突 | 按迁移段落处理旧版 Hook；脚本不会擅自改用户配置 |

### 已知边界

- UUIDv7 提供新会话创建时间；其他 ID 格式会被跳过，设备时间应正确。分叉/导入若获得新的 UUIDv7，也按新 ID 时间处理。
- 模型生成的标题、分类可能需要用户纠正；24 字为提示目标，不是字符串截断规则。
- 第一次侧栏观察之前发生的手动改名，可能没有机器标记；用户明确指定的名称优先，插件不能识别所有 UI 修改竞态。
- 当前观察按本地 `codex:thread:local:` 侧栏键匹配。部分桌面版本保留 `client-new-thread:` 临时键；v0.2.2 只读本机明确的临时 ID → 正式 ID 绑定进行匹配。绑定不可用时继续等待确认，不猜测归属；远程主机会话不在本版验收范围。
- Hook 不是所有工具路径的完整覆盖；只有原生回读匹配才标记完成。未回读/失败不会宣称成功，也不无限重试。
- 分区被删除时请重新运行设置技能更新映射；开启自动新建后，同 ID 改名可在准备/回读中登记新名，旧名称缺失不会自动重建。

## 首次命名与后续校准

v0.2.2 明确区分两个阶段：首次命名在完成首个实质任务后执行，不要求目标先发生变化；已有默认标题与空自动标题记录不构成手动改名证据。首次未完成的会话，下次实质任务完成后继续尝试；明确指定或已观察到的手动标题仍优先保护。首次回读确认后才进入后续校准。

## 持续目标校准

从 v0.2.0 起，首次命名后仍会在每轮实质任务完成时评估主线。v0.2.1 将持续目标明确为“本会话最终要达成的具体结果或交付物”，而不是最后一条消息的缩写或当前步骤。

只要本轮仍在服务原目标，就保持标题。只有主线明确转向、交付范围实质扩大或原目标被取代，导致旧标题明显失真，才更新右侧；不要求用户说出固定口令，但新主线必须有明确会话依据。临时支线、阶段变化和单纯润色不触发改名，不推断用户未提出或认可的更大目标。修复、测试、设计可作为核心结果，也可能只是推进步骤，按角色判断，不按动词机械分类。分区仍为一次确认。

例如：“建立会话自动整理机制”之下的规则修改、README 美化和补测试，仍保持原目标；用户决定交付可供他人安装的开源产品、旧目标已不足以概括时，才更新为“交付可安装的开源整理器”。如果会话本来就为解决登录闪退，“解决登录闪退”本身就是合理目标。

自然转向验收示例：在个人会话管理建议的会话中继续说“我们要让整个团队都用这套办法，请给出统一命名、责任分工和交接记录的协作规范”。检查模型是否依据会话判断新主线，而非依赖“目标改变”口令；随后要求改措辞，应保持新标题。这是建议验收步骤，不是已通过的语义测试记录。

升级复用 v0.1.0 的 `managed_title` 与完成状态，不清空数据、不重置首次接管时间。已有自动管理的会话在后续直接输入时参与校准；历史排除默认继续生效，只有明确开启旧会话整理后才在续聊时接入；已保护标题始终继续保留。

手动改名与明确指定标题优先。设置技能可先回读当前侧栏，再通过 `scripts/session_organizer.py --lock-title <会话ID>` 保护标题；只有用户明确要求恢复时，回读一个“主题对象｜持续目标”格式的标题，再运行 `--unlock-title <会话ID>`。脚本仍通过 `sh scripts/python.sh ...` 启动。

Hook 不独立调用另一个模型；主线变化由当前模型结合会话判断。每轮补充管理上下文，必要时读取侧栏；自动工具调用不是硬性拦截边界。手动变化与工具回读存在竞态，并不识别所有 UI 并发修改；未同轮确认的候选在下一轮作废，宁可保留观察到的标题。
