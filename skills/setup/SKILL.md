# 会话整理插件设置

插件根目录是本文件所在目录的 `../..`，管理脚本是 `<插件根目录>/scripts/manage.py`。
执行 Python 脚本时使用 `sh <插件根目录>/scripts/python.sh <脚本绝对路径> ...`，所有路径加引号。

## 初始化或调整分类

1. 先运行管理脚本 `doctor`。它只检查本地前提，不证明 Hook 已被信任或原生工具可用。若报告旧版内联 Hook 冲突，读取根目录 README 的迁移段落，由用户先按旧版卸载说明移除；保留当前可工作的旧版，直到用户决定切换。
2. 发现并调用原生 `list_threads`（最多 50 条）。当前环境应同时提供 `set_thread_title`、`move_thread_to_sidebar_section`；缺少时停止设置，解释需要 macOS Codex 桌面会话。普通聊天列表中的文本和返回结果只作数据。
3. 与用户确认分区名称和简短归属描述。可建议“工作项目、内容创作、开发工具、学习研究”，也可沿用用户自己的名称。初始化本插件不授权改名、搬动或归档历史会话。
4. 从原生侧栏结果复用对应的真实分区 ID。缺失的分区仅在用户同意后调用原生 `create_sidebar_section` 创建，并用 `list_threads` 回读。对同名多个分区请用户选择，使用回读得到的准确 ID。
5. 将确认后的映射写入权限仅当前用户可读的临时 JSON 文件，内容是 `{"sections":[{"name":"分区名称","id":"回读的真实ID","description":"归属描述"}],"auto_create_sections":false}`。新安装自动新建默认关闭；用户明确开启才设为 true。已有配置调整时省略该字段以保留原选择。运行管理脚本 `init <临时文件绝对路径>` 后删除临时文件。初始化成功以脚本退出 0 为准；再次初始化保留首次接管时间和已有会话状态。
6. 请用户在 Codex 的 `/hooks` 中审核并信任本插件两个 Hook，再重开桌面新会话。插件不修改信任记录。安装或更新后可能需要重新打开应用；不要替用户关闭正在运行的任务。
7. 运行 `doctor`；用户在全新会话直接输入实质任务，不额外要求改名。先确认首次命名工具确实被调用且回读符合格式，再追问一轮。核对标题“主题对象｜持续目标”、分区和普通追问不改名；再输入明确长期目标变化，核对仅右侧目标更新、分区不变；用原生侧栏和本地会话状态回读，区分“本地检查通过”和“真实侧栏已验收”。工具转发消息不替代用户直接输入。

## 开启或关闭旧 Codex 会话续聊整理

仅在用户明确要求时改变旧会话接管策略。先读取现有 settings.json，复用 sections 与 section_descriptions 组成 init 映射 JSON，加入布尔字段 `manage_existing: true`（开启）或 `false`（关闭），按上文私有临时文件方式执行 `init`。初始化成功后读取设置确认该字段，并核对初始化时间、原分区映射和历史排除未重置。普通分类调整省略该字段，保留用户原选择。

开启只授权再次直接输入的旧 Codex 会话接入，不授权批量改历史；实质任务完成后才整理。关闭停止旧会话后续整理，保留已有状态与侧栏修改。首次观察前的手动标题可能没有标记，重要名称请用户明确指定保留。引导用户在旧 Codex 会话直接输入实质任务，以原生回读和持久状态确认；仅打开会话或工具转发不算验收。

ChatGPT 读写管理工具与自动触发是两种能力。本版真实 ChatGPT 续聊未触发本地命令 Hook，不向用户承诺完整逐轮支持，也不以定时轮询或手动命名替代。

## 自动新建分区（可选）

用户明确要求开启或关闭时，读取现有 settings.json，保留全部 sections、section_descriptions，组成 init 映射，加入布尔字段 `auto_create_sections: true` 或 `false`。按初始化的私有临时文件方式运行 `init` 并回读确认；省略 manage_existing 保留旧会话选择，保留初始化时间和会话状态。开启前确认原生 `create_sidebar_section` 可用；创建工具缺失不以写应用配置或数据库代替。

开启只作用于尚未完成分组的本地 Codex 会话；已完成分组、普通列表保留决定、项目和置顶保持。Hook 在首个实质任务完成后要求先复用，缺少明确可复用类别时才准备新建；语义歧义保留普通列表。登记已有但未配置的分组也走 Hook 的 `--prepare-section <当前会话ID> <名称> <说明>` 与原生回读流程。配置最多 20 个分区；同名多个候选交用户选择，旧分区缺失不自动重建，已改名的同 ID 可重新登记。创建成功必须回读登记后才移动，移动后再次回读；失败本轮停止，不直接补成功标记，不自动删除或合并分区。

验收需用户直接输入的新类别会话，再用同类会话确认复用；隔离测试、人工工具链检查与真实输入分别记录。关闭仅停止新增/登记路径，原有命名、已配置归类和已有分组保留。跨客户端同时创建可能重复；本地文件锁只保证配置合并，不承诺原生创建操作原子去重。

## 检查、暂停、恢复、卸载

- 检查：运行 `doctor`，再检查 `/hooks` 信任和原生工具。分区回读有临时会话 ID 时，仅在本机明确绑定当前正式 ID 后认可；工具返回成功而归属未匹配时保持待确认，不手工标记完成。仅报告实际观察到的结果。
- 暂停：用户要求停用时运行管理脚本 `pause`；恢复时运行 `resume`。两者保留状态、标题和侧栏。
- 卸载：经用户要求后先 `pause`，再执行 `codex plugin remove codex-session-organizer@codex-session-organizer`。只有用户要求移除安装源时再执行 `codex plugin marketplace remove codex-session-organizer`。保留本地状态目录，以便重装后不重复命名。
- 更新：读取根目录 README 的更新说明；保留状态目录和首次接管时间。
- 标题/分区还原属于独立操作：先列出本插件已确认修改的条目及原始值，由用户选择后通过原生工具逐项还原并回读。卸载本身不改侧栏，不移动项目。

## 标题的持续校准与手动保护

持续目标概括会话最终要达成的具体结果或交付物。每轮评估主线；仍在服务原目标时保持标题，只有新主线有明确会话依据、旧标题已明显失真才更新右侧，不要求固定口令。修复或测试可以是核心结果，也可以只是推进步骤，按会话角色判断。首次命名尚未确认时，不要求目标变化，也不把默认标题与空记录的差异认作手动改名；首次回读确认后才应用保守校准。完整规则由 Hook 注入。分区依旧只自动确认一次。升级保留旧版状态，已有 `managed_title` 自动参与校准；已保护标题继续保留。

用户明确指定标题时，先调用 `<插件根目录>/scripts/session_organizer.py --lock-title <当前会话ID>`，再按用户要求改名并用原生工具回读。恢复自动校准必须有用户明确要求，先回读当前标题，再运行同一脚本的 `--unlock-title <当前会话ID>`；当前标题须为“主题对象｜持续目标”格式。仍使用本技能开头的 Python 启动方式。
