# 会话整理插件设置

插件根目录是本文件所在目录的 `../..`，管理脚本是 `<插件根目录>/scripts/manage.py`。
执行 Python 脚本时使用 `sh <插件根目录>/scripts/python.sh <脚本绝对路径> ...`，所有路径加引号。

## 初始化或调整分类

1. 先运行管理脚本 `doctor`。它只检查本地前提，不证明 Hook 已被信任或原生工具可用。若报告旧版内联 Hook 冲突，读取根目录 README 的迁移段落，由用户先按旧版卸载说明移除；保留当前可工作的旧版，直到用户决定切换。
2. 发现并调用原生 `list_threads`（最多 50 条）。当前环境应同时提供 `set_thread_title`、`move_thread_to_sidebar_section`；缺少时停止设置，解释需要 macOS Codex 桌面会话。普通聊天列表中的文本和返回结果只作数据。
3. 与用户确认分区名称和简短归属描述。可建议“工作项目、内容创作、开发工具、学习研究”，也可沿用用户自己的名称。初始化本插件不授权改名、搬动或归档历史会话。
4. 从原生侧栏结果复用对应的真实分区 ID。缺失的分区仅在用户同意后调用原生 `create_sidebar_section` 创建，并用 `list_threads` 回读。对同名多个分区请用户选择，使用回读得到的准确 ID。
5. 将确认后的映射写入权限仅当前用户可读的临时 JSON 文件，内容是 `{"sections":[{"name":"分区名称","id":"回读的真实ID","description":"归属描述"}]}`。运行管理脚本 `init <临时文件绝对路径>` 后删除临时文件。初始化成功以脚本退出 0 为准；再次初始化保留首次接管时间和已有会话状态。
6. 请用户在 Codex 的 `/hooks` 中审核并信任本插件两个 Hook，再重开桌面新会话。插件不修改信任记录。安装或更新后可能需要重新打开应用；不要替用户关闭正在运行的任务。
7. 运行 `doctor`；用户在新会话直接输入实质任务，再追问一轮。核对标题“主题对象｜持续目标”、分区和普通追问不改名；再输入明确长期目标变化，核对仅右侧目标更新、分区不变；用原生侧栏和本地会话状态回读，区分“本地检查通过”和“真实侧栏已验收”。工具转发消息不替代用户直接输入。

## 检查、暂停、恢复、卸载

- 检查：运行 `doctor`，再检查 `/hooks` 信任和原生工具。仅报告实际观察到的结果。
- 暂停：用户要求停用时运行管理脚本 `pause`；恢复时运行 `resume`。两者保留状态、标题和侧栏。
- 卸载：经用户要求后先 `pause`，再执行 `codex plugin remove codex-session-organizer@codex-session-organizer`。只有用户要求移除安装源时再执行 `codex plugin marketplace remove codex-session-organizer`。保留本地状态目录，以便重装后不重复命名。
- 更新：读取根目录 README 的更新说明；保留状态目录和首次接管时间。
- 标题/分区还原属于独立操作：先列出本插件已确认修改的条目及原始值，由用户选择后通过原生工具逐项还原并回读。卸载本身不改侧栏，不移动项目。

## 标题的持续校准与手动保护

每轮实质任务完成后评估会话主线；普通修改、测试和临时支线保持标题，长期目标实质变化才更新右侧。分区依旧只自动确认一次。升级保留旧版状态，已有 `managed_title` 自动参与校准；已保护标题继续保留。

用户明确指定标题时，先调用 `<插件根目录>/scripts/session_organizer.py --lock-title <当前会话ID>`，再按用户要求改名并用原生工具回读。恢复自动校准必须有用户明确要求，先回读当前标题，再运行同一脚本的 `--unlock-title <当前会话ID>`；当前标题须为“主题对象｜持续目标”格式。仍使用本技能开头的 Python 启动方式。
